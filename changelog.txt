Done:

Features:
- The space used for the material list on the Models tab can now be switched between four sub-tabs:
	- Materials function the same as before
	- Transform editor is the second subtab, rather than being a separate view
		- Since it's no longer necessary to go through the transform editor to edit tweens, the warning about not accidentally modifying models here has been removed
	- Third subtab is a list of all tweens on the model
		- Tweens no longer have to be created from a specific transform - Geomancer takes care of that in the background.
		- Tweens are displayed as [Tween name] ([signal]), sorted by name. Names can be freely changed
			- Maps saved with older Geomancer version will have their tweens named after the transform they were originally attached to
		- Tweens are coloured based on the predominant action type, based on length and number of actions
			- Tweens which target the same transform with the same type of action are coloured red, as that is almost certain to cause issues
		- You can now jump straight to tween preview with a button at the top of the tween sub-tab
		- Tweens without actions are automatically deleted (this can be turned off in settings)
		- The Tween button on the model list has been merged with the static/dynamic button and shows the number of tweens of each prop
			- Clicking it will no longer open the transform editor, swithcing to the tween submenu instead
	- The last subtab is Instances, replacing the dialog previously accessed by a button at the bottom of the model list
		- The list of instances is sorted by Z position and shows their Z / X / Y position and spawn/despawn times in seconds
		- There are buttons for each entry. Left to right:
			- Edit properties (wrench icon) opens up a dialog where you can view and adjust position, rotation and scale of the prop instance, as well as spawn and despawn times
				- The "Reasonable ranges" button automatically sets the times to margins that are generally safe.
					- They are similar (but not always the same) as the default values set by Pistol Mix
				- A text box under the spawn/despawn UI describes roughly when the prop comes into view taking draw distance into account, when it spawns/despawns in relation to those times and points out if the prop is likely to either pop-in or despawn prematurely
					- Note that this is only really accurate for small props placed directly in the player's path, at eye level. Large props will be visible sooner and may need adjustments.
				- The eye icon opens map preview and jumps to the prop's location.
				- You can browse through prop instances using the bottoms at the bottom
			- GEO button opens a geo creation dialog. See below.
			- View prop (eye icon) opens map preview and jumps to the prop's location.
			- Delete (trash can icon) deletes the prop instance from the map. Requires confirmation by default
- It is now possible to create geo (visible and/or invisible) from props, from the Instance subtab
	- Clicking the "Geo" button at the prop instance of your choice opens a dialog with options:
		- Select whether to generate visible geo, colliders or both
		- You may choose to delete the prop afterwards
		- Alternatively it can be automatically scaled to 0 to make it invisible, but still present in the map in case you want to reference it later
		- If there's more than one instance of this prop, you can generate geo from all of them at the same time
	- Geomancer keeps track of geo generated this way and will store this information in the geomancer metadata file on export
		- This allows it to regenerate these changes when importing changes from a previously geomanced map
		- There are also new buttons on the Geo/Colliders tab used to remove all geo created this way, as long as the metadata file is present
- There is an issue where saving a map without ever clicking "Generate geo" causes props and obstacles to disappear. Geomancer now automatically fixes this by generating empty geo chunks if there are none.
	- This means that it is no longer necessary to make a large subtractive volume if a map with no geo is desired. Just run the map through Geomancer and it will work.
- Importing models now allows you to select and .obj file rather than an existing map
	- Some models may fail to load. Try re-exporting them with blender if that happens
	- There is also an Import folder button, which will import all .obj files in the selected folder into the map
		- Models imported through Pistol Mix have their mesh transforms scale x set to -1. Geomancer modifies the mesh instead to get the same result
- There is a checkbox near the export button to remove the normal data from models when exporting
	- Normal data is not used by the game in any way and removing it will reduce the map size and speed up loading
	- Geomancer does use normals for previews and will automatically recalculate them (poorly) when opening a map
- Exports with overwrite are now done in a temporary folder first, then moved if there are no errors
	- This should prevent major errors during export from overwriting the previous copy of the map
- Obstacles are now shown in preview (can be hidden)
- Improved how colliders are rendered (textured and transparent)
	- Collider display can be enabled/disabled independently from geo
	- Obstacles have collider graphics attached
	- Red colliders (geo and obstacles) hurt the player when going through them
	- Yellow colliders (found on some built-in props) only block shots
		- Props named "PF_CollisionCube_01_Flat" and "PF_CollisionCube_02_tall" are hardcoded to show as appropriately-sized colliders
			- This only happens when loading map data. If such a model is imported or renamed, it will only show correctly after exporting and reloading the map
- Geo rendering in previews is more accurate to the game
- The find model dialog now opens with the text field selected
- Increased the maximum number of tween action repeats to 999
- Loading and exporting maps now reports time taken
